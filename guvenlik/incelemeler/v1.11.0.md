## Bulgular

- **Orta (iki okuyucu da buldu, doğrulandı, DÜZELTİLDİ), `ui/server.py` `_kaynak_guvenli`:** ağ kipinde
  (`--host 0.0.0.0 --ag-erisimine-izin-ver`) yeni eklenen `Origin == http://<Host>` kabulü DNS rebinding'e açıktı:
  saldırgan alan adı LAN IP'sine çözülürse tarayıcı Origin ve Host'u aynı saldırgan adıyla gönderir, yazma isteği
  geçerdi (okuyucular canlı 200/201 ile gösterdi). Düzeltme: Host'un ana bilgisayar kısmı bir IP literal
  (IPv4/IPv6) olmalı, alan adı 403. Rebinding alan adı gerektirir, IP literal Host'ta çalışmaz. Test:
  `test_ag_kipinde_rebinding_alan_adi_403`. Loopback kipi etkilenmedi.
- **Düşük (v1.11.0.md yok), düzeltildi:** bu kayıt yazıldı, ayrı commit olarak eklendi.
- **Düşük (v1.10.1 kabul edilen riskinin değişmesi):** v1.10.1 kaydında "ağ kipinde tarayıcı yazması Origin
  denetimine takılıyor, düzeltmesi kaynak denetimini gevşetmek demek" diye kabul edilmişti. v1.11.0 bunu bilinçli
  olarak gevşetiyor (aynı kökenli, IP ile açılmış sayfa yazabilir); yukarıdaki IP kısıtıyla rebinding yüzeyi
  kapatıldı. Karar burada açıkça kayda geçti.
- Temiz bulunanlar: DST tüm gün bitiş düzeltmesi (yalnız `all_day`, saatli davranış değişmedi); tatil verisi hiçbir
  yazma yoluna (ics, senkron, hatırlatıcı, arama) sızmıyor; ön yüzde tatil adları yalnız `textContent`/`title`
  (XSS yok, adlar gömülü sabit tablodan); `resmi_tatiller` ayarı bool tip denetimli; `takvim.spec`/`release.yml`
  değişikliği gerekmiyor.

## Kabul edilen riskler

- Ağ kipinde API kimliksiz: aynı ağdaki herkes doğrudan yazabilir/okuyabilir (AGENTS 65, değişmedi). Ağ kipi
  varsayılan değil, bayrak ve uyarıyla açılır. IP ile açılan ağ adresine yönelen tarayıcı tabanlı saldırı
  (saldırganın kurbanın LAN IP'sine sayfa yönlendirmesi) Origin farklı olduğundan 403 alır.
- `GET /api/export` ağ kipinde Host denetimi olmadan okunabilir (v1.10.1'den beri; değişmedi).
- Önceki kayıtlardaki kabul edilen riskler değişmedi.
